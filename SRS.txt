# Software Requirements Specification

## Simple Airbnb-like Rental Booking System

**Backend:** FastAPI
**Frontend:** React

---

## 1. Purpose

This system allows users to browse rental properties, view details, make bookings, and manage reservations. Hosts can list properties and manage bookings. Admins can monitor users, listings, and bookings.

---

## 2. Scope

The system is a simplified Airbnb-style platform with:

* User registration and login
* Property listing and browsing
* Search and filtering
* Property detail pages
* Booking creation
* Host listing management
* Admin management
* Basic payment-status tracking, not real payment integration

---

## 3. User Roles

| Role       | Description                                         |
| ---------- | --------------------------------------------------- |
| Guest/User | Can search properties, view details, and book stays |
| Host       | Can create, edit, and delete property listings      |
| Admin      | Can manage users, listings, and bookings            |

---

## 4. Core Features

## 4.1 Authentication

### Requirements

* Users can register using name, email, password, and role.
* Users can log in using email and password.
* System returns JWT access token after login.
* Passwords must be hashed.
* Protected routes require authentication.

### API Examples

| Method | Endpoint         | Description      |
| ------ | ---------------- | ---------------- |
| POST   | `/auth/register` | Register user    |
| POST   | `/auth/login`    | Login            |
| GET    | `/auth/me`       | Get current user |

---

## 4.2 User Management

### Requirements

* Users can view and update their profile.
* Admin can view all users.
* Admin can deactivate users.

### API Examples

| Method | Endpoint                       | Description          |
| ------ | ------------------------------ | -------------------- |
| GET    | `/users/me`                    | Get own profile      |
| PUT    | `/users/me`                    | Update own profile   |
| GET    | `/admin/users`                 | Admin gets all users |
| PATCH  | `/admin/users/{id}/deactivate` | Deactivate user      |

---

## 4.3 Property Listings

### Requirements

Hosts can create listings with:

* Title
* Description
* Location
* Price per night
* Number of guests
* Number of bedrooms
* Number of bathrooms
* Amenities
* Images
* Availability status

Users can browse all active listings.

### API Examples

| Method | Endpoint           | Description            |
| ------ | ------------------ | ---------------------- |
| GET    | `/properties`      | List/search properties |
| GET    | `/properties/{id}` | Get property detail    |
| POST   | `/properties`      | Host creates property  |
| PUT    | `/properties/{id}` | Host updates property  |
| DELETE | `/properties/{id}` | Host deletes property  |

---

## 4.4 Search and Filtering

### Requirements

Users can filter listings by:

* Location
* Check-in date
* Check-out date
* Price range
* Number of guests
* Property type
* Amenities

### Example Query

```http
GET /properties?location=Kathmandu&guests=2&min_price=30&max_price=100
```

---

## 4.5 Booking Management

### Requirements

Users can book a property by selecting:

* Property
* Check-in date
* Check-out date
* Number of guests

System must:

* Check availability
* Prevent overlapping bookings
* Calculate total price
* Store booking status

Booking statuses:

* `pending`
* `confirmed`
* `cancelled`
* `completed`

### API Examples

| Method | Endpoint                | Description                              |
| ------ | ----------------------- | ---------------------------------------- |
| POST   | `/bookings`             | Create booking                           |
| GET    | `/bookings/me`          | User views own bookings                  |
| GET    | `/host/bookings`        | Host views bookings for their properties |
| PATCH  | `/bookings/{id}/cancel` | Cancel booking                           |

---

## 4.6 Reviews and Ratings

### Requirements

* Users can review a property after completed booking.
* Review includes rating from 1 to 5 and comment.
* Average rating is shown on property detail page.

### API Examples

| Method | Endpoint                   | Description   |
| ------ | -------------------------- | ------------- |
| POST   | `/reviews`                 | Create review |
| GET    | `/properties/{id}/reviews` | Get reviews   |

## 7. Business Rules

* A user cannot book their own property.
* A booking cannot overlap with another confirmed booking.
* Check-out date must be after check-in date.
* Reviews are allowed only after completed bookings.
* Only hosts can create listings.
* Only the property owner can edit or delete their listing.
* Admin can deactivate users or listings.
* Cancelled bookings should not block availability.

---

## 8. Non-Functional Requirements

## 8.1 Security

* Passwords must be hashed using bcrypt.
* JWT must be used for authentication.
* Role-based access control is required.
* Backend must validate all inputs.
* CORS must allow only approved frontend domains.

## 8.2 Performance

* Property search should respond within 1 second for normal load.
* Pagination should be used for listing pages.
* Images should be stored externally or served through object storage.

## 8.3 Reliability

* Booking creation must be transaction-safe.
* Duplicate bookings must be prevented.
* API errors must return clear status codes and messages.

## 8.4 Scalability

* Backend should follow modular FastAPI structure.
* Database indexes should exist on:

  * `property.location`
  * `booking.property_id`
  * `booking.check_in`
  * `booking.check_out`
  * `user.email`

## 11. Acceptance Criteria

The system is acceptable when:

* Users can register and log in.
* Guests can search and view properties.
* Hosts can create, update, and delete listings.
* Users can create bookings.
* The system prevents double bookings.
* Users can view booking history.
* Hosts can view bookings for their properties.
* Reviews can be submitted after completed bookings.
* Admin can manage users, listings, and bookings.
* Frontend communicates successfully with FastAPI backend.
